## UNDERSTAND

A **genuine comparison** compares samples of the same identity. An **impostor comparison** compares different identities. A similarity score is larger when samples look more alike; it is not a probability.

A **threshold** is the cut-off for a decision. Here we accept when score ≥ threshold. A genuine rejection is an error. An impostor acceptance is also an error. Raising the threshold trades fewer impostor accepts for more genuine rejects.

We count completed 1:1 comparisons. Their precise error names are **FMR** (false match rate) and **FNMR** (false non-match rate). FAR and FRR are often used for these rates in papers, but operational transactions can include capture failures and retries. Always state what was counted.

In this toy lesson, each transaction has one completed comparison and no capture failures, so FAR = FMR and FRR = FNMR. Do not assume that equality for every deployed system.

## MECHANISM

Labelled scores → compare each with threshold → count four outcomes → divide by the correct group total → report rates.

- **FAR/FMR:** accepted impostors / all impostor comparisons.
- **FRR/FNMR:** rejected genuine / all genuine comparisons.
- **TAR:** accepted genuine / all genuine comparisons.

TAR + FRR = 1 here because each genuine comparison is either accepted or rejected. FAR + TAR does not have to equal 1: their denominators are different.

Move the threshold below and inspect every sample decision. A score exactly equal to the threshold is accepted under our ≥ rule.

## WORKED EXAMPLE

Use four genuine scores [0.90, 0.70, 0.50, 0.40] and five impostor scores [0.10, 0.30, 0.50, 0.60, 0.20]. These are synthetic teaching values, not research measurements.

At threshold 0.50, genuine decisions are [accept, accept, accept, reject]. Thus TAR = 3/4 = **75%**, and FRR = 1/4 = **25%**.

Impostor decisions are [reject, reject, accept, accept, reject]. Thus FAR = 2/5 = **40%**. Dividing by all nine comparisons would give 2/9, which answers a different question.

```python
genuine = [0.90, 0.70, 0.50, 0.40]
impostor = [0.10, 0.30, 0.50, 0.60, 0.20]
t = 0.50

ta = sum(s >= t for s in genuine)
fa = sum(s >= t for s in impostor)
fr = len(genuine) - ta
print("genuine accepted:", ta, "rejected:", fr)
print("impostor accepted:", fa, "rejected:", len(impostor) - fa)
print(f"FAR/FMR: {fa}/{len(impostor)} = {fa / len(impostor):.0%}")
print(f"FRR/FNMR: {fr}/{len(genuine)} = {fr / len(genuine):.0%}")
print(f"TAR: {ta}/{len(genuine)} = {ta / len(genuine):.0%}")
```

Output:

```text
genuine accepted: 3 rejected: 1
impostor accepted: 2 rejected: 3
FAR/FMR: 2/5 = 40%
FRR/FNMR: 1/4 = 25%
TAR: 3/4 = 75%
```

Each comparison produces True or False. Python treats True as 1 and False as 0 when summing, so `sum(s >= t ...)` counts acceptances. `len` counts the whole group. Formatting as .0% displays a fraction as a percentage.

## COMMON MISTAKES

- **Using all comparisons as the denominator:** false accepts belong to the impostor group; false rejects belong to the genuine group.
- **Replacing ≥ with >:** the samples at 0.50 change decisions. State the rule and use it consistently.
- **Calling 0/5 proof of zero risk:** five trials provide little evidence. A zero observed rate does not prove a zero population error rate.
- **Selecting a research threshold here or on dorsal test data:** this slider teaches arithmetic only. In your project, select on eligible source development data, freeze it, then evaluate dorsal without tuning.
- **Using these rates for 1:N search:** identification counts search events and uses different metrics such as FPIR/TPIR.
